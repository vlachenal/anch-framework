Detailed Description

REST API: endpoints declaration and routing, independent of the HTTP server.

Endpoints are declared with a method and a path pattern where path parameters are named between braces (/pets/{id} ). Empty path segments are ignored (/pets/ is /pets ). On routing, a literal segment has priority over a parameter.

anch::rest::Api api;
api.get("/pets/{id}", [](uint64_t id) -> std::optional<Pet> { return findPet(id); })
.produces<anch::rest::Json>();
api.post("/pets", [](anch::rest::Body<Pet> pet) { return savePet(*pet); })
.consumes<anch::rest::Json>().produces<anch::rest::Json>();
api.validate();

Endpoint arguments and results are described in Endpoint .

handle never throws: an HttpException is answered with its status, any other exception with 500 . No route for path is 404 , no route for method is 405 (with Allow header). HEAD requests are answered by GET endpoints without body.

Routes and filters have to be declared before handling requests; handle can then be called from several threads.
