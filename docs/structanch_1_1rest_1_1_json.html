Detailed Description

application/json codec based on anch-json: values need an anch-json mapper (anch::json::registerObject ).

Server and client use mapping options of their side ( options ): fields constraints ( anch::json::required , anch::json::minLength , ...) are checked on values the server receives (invalid request body: 400 response with the path of the invalid value) and on values the client sends (invalid request is not sent: anch::json::MappingError is raised by Call::body ). Server responses are not checked by the server (a response which violates constraints is still sent) nor by the client (server responses are trusted).

anch::json::MappingOptions & anch::rest::Json::options ( anch::rest::Side side)
static

Mapping options of a side. They are copied from anch::json::DEFAULT_MAPPING_OPTIONS on first use, then constraints checks are set:

  • server: deserialize_check_constraints is true , serialize_check_constraints is false ;
  • client: serialize_check_constraints is true , deserialize_check_constraints is false . Server responses are trusted and read with tolerance: unknown fields are ignored ( deserialize_ignore_unknown_field is true ) and whitespaces are accepted ( deserialize_max_discard_char is -1 ).

Options can be changed at application initialization (they are not protected against concurrent changes).
