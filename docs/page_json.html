AnCH JSON library documentation

Introduction

AnCH JSON library is JSON serialization and deserialization library for JSON format.

Prerequisites

AnCH JSON is a standalone library.

Installation

CMake target anch::json:

find_package(Anch REQUIRED)
target_link_libraries(my-app PRIVATE anch::json)

See installation.

Conception

Serialized fields are declared by specializing anch::json::registerObject for each type: fields are registered with their JSON key and their member pointer (or a getter function). Containers and std::optional fields give their value type as template argument.

anch::json::serialize writes JSON in a stream or returns a string ; anch::json::deserialize reads a stream and raises anch::json::MappingError on invalid JSON (with its position). Mapping options (anch::json::MappingOptions ) control unknown fields, null values and limits (depth, payload size).
With ANCH_UUID and ANCH_DATE options, anch::UUID , anch::date::Date and std::chrono::year_month_day are mapped as strings (RFC 3339 for dates).

Examples

#include "json/json.hpp"
#include <iostream>
#include <optional>
#include <sstream>
#include <string>
#include <vector>
struct Pet {
uint64_t id;
std::string name;
std::vector<std::string> tags;
std::optional<std::string> owner;
};
// Declare serialized fields (once per type)
template<>
void
anch::json::registerObject(anch::json::ObjectMapper<Pet>& mapper) {
mapper
.registerField("id", &Pet::id)
.registerField("name", &Pet::name)
.registerField<std::string>("tags", &Pet::tags) // container: element type is given
.registerField<std::string>("owner", &Pet::owner); // std::optional: value type is given too
}
int
main() {
Pet pet{1, "Rex", {"dog", "good boy"}, std::nullopt};
std::string json = anch::json::serialize(pet);
std::cout << json << std::endl;
std::istringstream input(R"({"id":2,"name":"Médor","tags":["cat"],"owner":"Vincent"})");
Pet parsed = anch::json::deserialize<Pet>(input); // anch::json::MappingError when invalid
std::cout << parsed.name << " " << parsed.owner.value_or("-") << std::endl;
return 0;
}

Required fields and error path

Constraints can be given when a field is registered. anch::json::required checks on deserialization that the field is present (error code MISSING_FIELD , every missing field is listed in the message) and that its value is not null , unless the field can hold null ( std::optional , std::shared_ptr , std::unique_ptr or pointer ; error code CONSTRAINT_VIOLATION ). Fields which are not required are not checked: a null value leaves them unchanged.

anch::json::MappingError::getPath gives the JSON Pointer (RFC 6901) of the value in error, from the deserialized root value ; what() starts with this path.

struct Pet {
uint64_t id;
std::string name;
std::optional<std::string> owner;
};
struct Shelter {
std::vector<Pet> pets;
};
template<>
void
anch::json::registerObject(anch::json::ObjectMapper<Pet>& mapper) {
mapper
.registerField("id", &Pet::id, anch::json::required)
.registerField("name", &Pet::name, anch::json::required)
.registerField<std::string>("owner", &Pet::owner, anch::json::required); // has to be present, can be null
}
template<>
void
anch::json::registerObject(anch::json::ObjectMapper<Shelter>& mapper) {
mapper
.registerField<Pet>("pets", &Shelter::pets, anch::json::required);
}
int
main() {
for(const char* json : {R"({"pets":[{"id":1,"name":"Rex","owner":null},{"id":2,"owner":"Vincent"}]})",
R"({"pets":[{"id":1,"name":null,"owner":null}]})"}) {
try {
std::istringstream input(json);
[[maybe_unused]] Shelter shelter = anch::json::deserialize<Shelter>(input);
} catch(const anch::json::MappingError& error) {
std::cout << error.getPath() << " -> " << error.what() << std::endl;
}
}
return 0;
}

Value constraints

Value constraints are given at registration too (header json/constraints.hpp ). They are checked after the field value has been read and raise anch::json::MappingError with CONSTRAINT_VIOLATION error code. null and absent values are not checked ( anch::json::required checks presence). Constraints are checked at compile time against the field type: minLength on an integer field does not compile.

Patterns use std::regex (ECMAScript grammar, on bytes: no UTF-8 character classes) by default: anch::json::setPatternCompiler plugs another engine. Formats are checked by validators registered with anch::json::registerFormat ( email , hostname , ipv4 , ipv6 , uri , byte , and uuid , date-time , date with ANCH_UUID / ANCH_DATE are built-in) ; unknown formats are not checked.
Integers bounds are compared without conversion (an uint64_t field accepts minimum(-1) ).

struct Pet {
std::string name;
int32_t age;
std::vector<std::string> tags;
std::map<std::string,int64_t> scores;
std::optional<std::string> color;
};
template<>
void
anch::json::registerObject(anch::json::ObjectMapper<Pet>& mapper) {
mapper
.registerField("name", &Pet::name, anch::json::required, anch::json::minLength(1), anch::json::maxLength(32))
.registerField("age", &Pet::age, anch::json::minimum(0), anch::json::maximum(50))
.registerField<std::string>("tags", &Pet::tags, anch::json::maxItems(5), anch::json::uniqueItems,
anch::json::items(anch::json::minLength(1))) // checked on every tag
.registerField<int64_t>("scores", &Pet::scores, anch::json::items(anch::json::multipleOf(5)))
.registerField<std::string>("color", &Pet::color, anch::json::allowed({"black", "white"})); // checked when not null
}
int
main() {
for(const char* json : {R"({"name":"Rex","age":3,"tags":["dog",""]})",
R"({"name":"Rex","age":3,"scores":{"agility":12}})",
R"({"name":"Rex","age":-1})",
R"({"name":"Rex","color":"brown"})"}) {
try {
std::istringstream input(json);
[[maybe_unused]] Pet pet = anch::json::deserialize<Pet>(input);
} catch(const anch::json::MappingError& error) {
std::cout << error.what() << std::endl;
}
}
return 0;
}

Constraints checks on deserialization and serialization

Constraints ( anch::json::required and value constraints) are checked according to mapping options:

  • deserialize_check_constraints (default true ): after values have been read ;
  • serialize_check_constraints (default false ): before values are written. The error has no input excerpt (message is "<path>: <constraint message>" ) and the output contains the JSON written before the error.

Required fields are always written, even when empty: null for empty std::optional and pointers, [] and {} for empty containers, whatever serialize_null and serialize_empty_col options are (the document would be refused by the other side otherwise).

Server side checks what it receives and trusts what it builds (default options). Client side checks what it sends and trusts server responses:

anch::json::MappingOptions client;
client.serialize_check_constraints = true; // invalid requests are not sent
client.deserialize_check_constraints = false; // responses are trusted

Validation

anch::json::validate checks an object without serializing it: constraints of its fields and of its nested values (objects, collections items, maps values, std::optional and pointers values). Unlike serialization and deserialization checks, it does not stop on the first violation: every violation is returned with its path. Mapping options are not used. Fields registered with a setter only are not checked, and required fields are not checked (an object always has its fields). anch::json::isValid returns true when there is no violation.

struct Pet {
std::string name;
int32_t age = 0;
std::vector<std::string> tags;
};
struct Shelter {
std::vector<Pet> pets;
};
template<>
void
anch::json::registerObject(anch::json::ObjectMapper<Pet>& mapper) {
mapper
.registerField("name", &Pet::name, anch::json::required, anch::json::minLength(1))
.registerField("age", &Pet::age, anch::json::minimum(0))
.registerField<std::string>("tags", &Pet::tags, anch::json::items(anch::json::minLength(1)));
}
template<>
void
anch::json::registerObject(anch::json::ObjectMapper<Shelter>& mapper) {
mapper
.registerField<Pet>("pets", &Shelter::pets, anch::json::maxItems(10));
}
int
main() {
Shelter shelter{{Pet{"Rex", 3, {"dog"}}, Pet{"", -1, {"cat", ""}}}};
for(const anch::json::Violation& violation : anch::json::validate(shelter)) { // every violation
std::cout << violation.path << ": " << violation.message << std::endl;
}
return 0;
}
