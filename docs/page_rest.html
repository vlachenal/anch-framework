AnCH REST library documentation

Introduction

AnCH REST library declares REST APIs independently of HTTP servers, and provides an HTTP client over native HTTP libraries (see anch-rest.todo for the work in progress).

Libraries

  • anch-rest-common : HTTP model (Method, Status, Headers, MediaType, Request, Response) and codecs (Json based on anch-json, Text).
  • anch-rest-server : endpoints declaration and routing (Api).
  • anch-rest-client : HTTP client (Client) over a Transport.
  • anch-rest-curl : libcurl transport (CurlTransport), option ANCH_REST_CURL .
  • anch-rest-nginx : nginx applications bridge (ANCH_REST_APPLICATION ), option ANCH_REST_NGINX , and nginx module sources (nginx/ , installed in share/anch/nginx-module ).

Endpoints declaration

Endpoints are declared with a method and a path pattern. Endpoint function arguments are bound from the request: [const Request&], path parameters..., [Body<T>]. The result is serialized with the codec negotiated with Accept header:

anch::rest::Api api;
api.get("/pets/{id}", [](uint64_t id) -> std::optional<Pet> { return findPet(id); }) // 404 when empty
.produces<anch::rest::Json>();
api.post("/pets", [](anch::rest::Body<Pet> pet) {
Pet saved = savePet(*pet);
return anch::rest::Response(anch::rest::Status::CREATED)
.header(anch::rest::header::LOCATION, "/pets/" + std::to_string(saved.id));
})
.consumes<anch::rest::Json>();
api.filter([](anch::rest::Request& request, const anch::rest::Next& next) {
if(!request.getHeaders().has(anch::rest::header::AUTHORIZATION)) {
return anch::rest::Response(anch::rest::Status::UNAUTHORIZED);
}
return next(request);
});
api.validate(); // every endpoint has its codecs
anch::rest::Request request(anch::rest::Method::GET, "/pets/1");
anch::rest::Response response = api.handle(request); // done by HTTP server adapter

Client

Path placeholders are replaced in order and percent-encoded. Accepted codecs are part of the call type: as<T>() is checked at compile time and deserializes the response with the codec matching its Content-Type :

anch::rest::TransportConfig config;
config.timeout = std::chrono::seconds(5);
anch::rest::Client client(std::make_unique<anch::rest::CurlTransport>(config), "https://api.example.com/v1");
client.filter(anch::rest::bearerAuth(token));
Pet pet = client.get("/pets/{id}", 42).accept<anch::rest::Json>().as<Pet>(); // HttpError when status >= 400
anch::rest::Response created = client.post("/pets").body<anch::rest::Json>(pet).send();
client.del("/pets/{id}", 42).execute();

Fields constraints

anch-json fields constraints ( anch::json::required , anch::json::minLength , ...) are checked by the Json codec according to the side which uses it ( Side ):

  • server: request bodies are checked (invalid body: 400 response, its body is the error message with the path of the invalid value, such as /name: Length 0 is lower than minLength 1), responses are not ;
  • client: request bodies are checked before being sent ( body<Json>(value) raises anch::json::MappingError , nothing is sent), server responses are trusted and read with tolerance (unknown fields are ignored, indented responses are accepted).

Each side has its own mapping options (server and client can run in the same process), which can be changed at application initialization:

anch::rest::Json::options(anch::rest::Side::SERVER).serialize_check_constraints = true; // also check responses
anch::rest::Json::options(anch::rest::Side::CLIENT).deserialize_ignore_unknown_field = false; // strict client

nginx module

An application is a shared library which declares its API factory:

std::unique_ptr<anch::rest::Api>
createApi(std::string_view config) { // config: second anch_rest_app argument
auto api = std::make_unique<anch::rest::Api>();
api->get("/api/pets/{id}", findPet).produces<anch::rest::Json>(); // routes see the whole URI
return api;
}
ANCH_REST_APPLICATION(createApi)

The module is built with nginx (--with-threads to execute handlers in a thread pool):

./configure --with-threads --with-compat --add-dynamic-module=<anch-rest/nginx>
make modules
