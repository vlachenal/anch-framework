AnCH SQL library documentation

Introduction

AnCH SQL library aims to provide facilities to manage SQL database interactions.

Prerequisites

anch-utils (connection pool), anch-conf (connection factory configuration) and the client library of each driver: libmariadb (or libmysqlclient), libpq and libsqlite3.

Installation

CMake target anch::sql, option ANCH_BUILD_SQL ; drivers anch::mysql , anch::postgresql and anch::sqlite are loaded at runtime:

find_package(Anch REQUIRED)
target_link_libraries(my-app PRIVATE anch::sql)

See installation.

Conception

AnCH SQL library is a layer to manage SQL client. Managed SQL clients are SQLite3, PostgreSQL and MySQL/MariaDB.

SQl interfaces are inspired by Java JDBC. You will find Connection, ResultSet,, PreparedStatement and SqlException. ResultSet can be handle with row mapper and complete extract std::function "std::function" trough queryMapRow and queryExtract methods. These methods will release ResultSet.

AnCH SQL provides connection factory.

Prepared statements

Prepared statements use '?' placeholders, numbered from 1 . Their number is given by the database (MySQL and SQLite count them on the server side) ; for PostgreSQL, '?' outside string literals, quoted identifiers and comments are replaced by $n (see anch::sql::findPlaceholders ). PostgreSQL '?' operators (jsonb ) can not be used in prepared statements: use their functions (jsonb_exists , ...) instead.
Every parameter has to be bound before execution ; NULL is bound with setNull , a NULL pointer or an empty std::optional .

Errors

Errors raise SqlException and are reported to the connection, from its prepared statements and result sets too. A fatal error (SqlException::isOK is false : connection lost or killed, server shutdown, out of memory, protocol error) invalidates the connection. Other errors keep it valid.

Transactions

Without Connection::startTransaction (or begin ), each query is committed by the database (auto-commit mode). A transaction is committed only by Connection::commit : a transaction which is not ended when the connection is released (returned to its pool or destroyed) is rolled back, with or without error, so that an application exception between two queries does not commit partial work.

SQL connection pool

SQL connection pools are configured in configuration file dbCon.conf
When a connection is returned to its pool, Connection::release rolls back its unfinished transaction, then invalid connections are destroyed instead of being reused.

Prepared statements cache

Each connection keeps its prepared statements in a bounded cache (statement-cache-size key of the connection section, 256 by default, Connection::setStatementCacheSize ). The least recently used statement is evicted and deallocated on the server side when the cache is full ; a statement is not evicted while one of its result sets is alive. Queries built with literal values (IN lists of the builder for example) are distinct cache entries: bind values with ? placeholders whenever possible.

Example

SQL connection example:

#include "sql/postgresqlConnection.hpp"
#include <iostream>
#include <functional>
#include <list>
#include <optional>
#include <string>
using anch::sql::Connection;
using anch::sql::PostgreSQLConnection;
using anch::sql::SqlException;
using anch::sql::ResultSet;
class Person {
public:
uint32_t _id;
std::string _firstName;
std::string _lastName;
std::string _birthDate;
std::string _email;
public:
Person(): _id(), _firstName(), _lastName(), _birthDate(), _email() {}
virtual ~Person() {}
inline uint32_t getId() const {return _id;}
inline void setId(uint32_t id) {_id = id;}
inline const std::string& getFirstName() const {return _firstName;}
inline void setFirstName(const std::string& firstName) {_firstName = firstName;}
inline const std::string& getLastName() const {return _lastName;}
inline void setLastName(const std::string& lastName) {_lastName = lastName;}
inline const std::string& getBirthDate() const {return _birthDate;}
inline void setBirthDate(const std::string& birthDate) {_birthDate = birthDate;}
inline const std::string& getEmail() const {return _email;}
inline void setEmail(const std::string& email) {_email = email;}
};
int
main(void) {
std::cout << "Enter in PostgreSQL unit tests" << std::endl << std::endl;
try {
anch::sql::SqlConnectionConfiguration config;
config.driver = "PostgreSQL";
config.database = "anch_test";
config.hostname = "localhost";
config.port = 5432;
config.user = "anch";
config.password = "anch";
PostgreSQLConnection dbCon(config);
std::cout << "Connected to database" << std::endl;
// Without transaction, each query is committed by the database (auto-commit mode)
dbCon.update("UPDATE T_Test SET email = ? WHERE first_name = ?", "john@anch.org", "John");
// A transaction is committed only by commit(): an unfinished transaction is rolled back when the connection is
// released (returned to its pool or destroyed), even without SQL error
dbCon.begin();
try {
dbCon.update("INSERT INTO T_Test (first_name,last_name,birth_date) VALUES (?,?,?)", "Jane", "Doe", "1971-01-01");
dbCon.update("INSERT INTO T_Test (first_name,last_name,birth_date) VALUES (?,?,?)", "Jack", "Doe", "1972-01-01");
dbCon.commit();
} catch(...) {
dbCon.rollback();
throw;
}
std::cout << std::endl;
std::cout << "Execute 'SELECT id,first_name,last_name,birth_date,email FROM T_Test' with manual result handling" << std::endl;
ResultSet* res = dbCon.query("SELECT id,first_name,last_name,birth_date,email FROM T_Test");
int row = 0;
std::string nullStr("NULL");
while(res->next()) {
std::cout << "Row " << row << std::endl;
std::optional<uint32_t> id = res->get<uint32_t>(0);
std::cout << "id=" << (id ? std::to_string(*id) : nullStr) << std::endl;
std::optional<std::string> fName = res->get<std::string>(1);
std::cout << "first name=" << fName.value_or(nullStr) << std::endl;
std::optional<std::string> lName = res->get<std::string>(2);
std::cout << "last name=" << lName.value_or(nullStr) << std::endl;
std::optional<std::string> bDate = res->get<std::string>("birth_date");
std::cout << "birth date=" << bDate.value_or(nullStr) << std::endl;
std::optional<std::string> email = res->get<std::string>(4);
std::cout << "email=" << email.value_or(nullStr) << std::endl;
row++;
}
delete res;
std::cout << std::endl;
std::cout << "Execute 'SELECT id,first_name,last_name,birth_date,email FROM T_Test' with per row result handling" << std::endl;
std::list<Person> persons;
dbCon.queryMapRow("SELECT id,first_name,last_name,birth_date,email FROM T_Test", [&persons](ResultSet& resSet) {
Person person;
resSet.get<uint32_t>(0,person._id);
resSet.get<std::string>(1, person._firstName);
resSet.get<std::string>(2, person._lastName);
resSet.get<std::string>(3, person._birthDate);
resSet.get<std::string>(4, person._email);
persons.push_back(person);
});
std::cout << "Found " << persons.size() << " persons." << std::endl;
for(const Person& pers : persons) {
std::cout << "Person " << pers._id << ":" << std::endl;
std::cout << "first name: " << pers._firstName << std::endl;
std::cout << "last name: " << pers._lastName << std::endl;
std::cout << "birth data: " << pers._birthDate << std::endl;
std::cout << "email: " << pers._email << std::endl;
}
std::cout << std::endl;
std::cout << "Execute 'SELECT id,first_name,last_name,birth_date,email FROM T_Test' with result set extracting" << std::endl;
dbCon.queryExtract("SELECT id,first_name,last_name,birth_date,email FROM T_Test", [](ResultSet& resSet) {
while(resSet.next()) {
Person pers;
resSet.get<uint32_t>(0,pers._id);
resSet.get<std::string>(1, pers._firstName);
resSet.get<std::string>(2, pers._lastName);
resSet.get<std::string>(3, pers._birthDate);
resSet.get<std::string>(4, pers._email);
std::cout << "Person " << pers._id << ":" << std::endl;
std::cout << "first name: " << pers._firstName << std::endl;
std::cout << "last name: " << pers._lastName << std::endl;
std::cout << "birth data: " << pers._birthDate << std::endl;
std::cout << "email: " << pers._email << std::endl;
}
});
std::cout << std::endl;
} catch(const SqlException& e) {
std::cerr << "Error: " << e.what() << std::endl;
return 1;
}
std::cout << "Exit PostgreSQL unit tests" << std::endl;
return 0;
}
